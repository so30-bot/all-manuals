Ошибка DISM 0x800f081f означает, что Windows знает, какие компоненты повреждены, но не может найти подходящие файлы для восстановления. В журнале это часто выглядит как `Source files could not be found`: DISM готов чинить компонентное хранилище, но источник восстановления не совпадает с установленной системой или недоступен.

Частая ошибка пользователей — скачивать любой ISO Windows и сразу подставлять его в `/Source`. Такой источник не подойдет, если отличается язык, редакция, канал обновлений или номер сборки. Особенно это заметно на системах после крупных feature update, где ISO старее установленной Windows.

Правильный порядок такой: сначала проверить образ, затем попробовать обычный `RestoreHealth`, потом подобрать официальный ISO той же версии и указать точный индекс `install.wim` или `install.esd`. После успешного DISM нужно запускать SFC, потому что именно SFC чинит конкретные системные файлы, используя уже восстановленное хранилище компонентов.

Если компьютер находится в домене или использует WSUS, проверьте политики восстановления компонентов. Организация может запретить скачивание файлов из Microsoft Update, и тогда DISM будет постоянно завершаться 0x800f081f без локального источника. На домашних ПК похожий эффект дают прокси, VPN, поврежденный кэш Windows Update или блокировка Microsoft Update в настройках сети.

Не удаляйте папку WinSxS вручную. Она является хранилищем компонентов Windows, и ручная чистка почти всегда ухудшает ситуацию. Используйте только DISM, Windows Update, официальный ISO и штатные команды очистки компонентов.

## Как выбрать правильный источник

Сначала определите текущую редакцию и сборку Windows. Для редакции подходит `DISM /Online /Get-CurrentEdition`, для номера сборки — `winver`. Затем скачайте ISO той же версии Windows с официального сайта Microsoft или через Media Creation Tool. Если установлен Windows 11 Pro на русском языке, источник от Windows 11 Home или ISO другого языка может не подойти.

После монтирования ISO проверьте, какой файл лежит в папке `sources`: `install.wim` или `install.esd`. Оба варианта допустимы, но в команде нужно явно указать правильный тип источника: `wim:` для WIM и `esd:` для ESD. Индекс внутри файла должен соответствовать установленной редакции.

## Что смотреть в логах

Если команда снова падает, откройте `C:\Windows\Logs\DISM\dism.log` и найдите строки рядом с 0x800f081f. В них обычно видно, какой источник использовался, какой package не найден и пытался ли DISM обращаться к Windows Update. Для SFC полезен файл `C:\Windows\Logs\CBS\CBS.log`, но читать его лучше после завершения DISM.

Когда DISM сообщает, что источник не найден, не повторяйте одну и ту же команду много раз. Меняйте только один параметр: сначала проверьте индекс, затем путь, затем соответствие ISO, затем доступ к Microsoft Update. Так проще понять, какое изменение реально решило проблему.

## Контрольный чек-лист

- ISO совпадает с установленной сборкой, редакцией и языком Windows.
- Выбран правильный индекс `install.wim` или `install.esd`.
- В команде указан правильный тип источника: `wim:` или `esd:`.
- `RestoreHealth` завершился без ошибки 0x800f081f.
- После DISM выполнен `sfc /scannow`.
- Windows Update снова устанавливает обновления.
- В логах DISM нет повторяющихся ошибок source not found.

## Когда лучше остановиться

- DISM просит источник от другой редакции Windows: сначала подберите корректный ISO.
- Компьютер управляется доменом или WSUS: проверьте политики, прежде чем менять source.
- В логах есть ошибки диска: сначала проверьте накопитель, затем повторяйте восстановление.
- Нет резервной копии важных данных: сделайте ее перед сбросом Windows Update или repair install.
- DISM снова просит source после успешного SFC: сравните номера сборок ISO и установленной системы.
